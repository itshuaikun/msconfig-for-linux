# 架构与 CachyOS 适配审查

审查基线：上游 `5a6ea20`（Add MIT License）。目标环境：CachyOS、KDE Plasma、Wayland、systemd、Limine 12.10.0；安装有 limine-mkinitcpio-hook 与 limine-snapper-sync。

## 判断

适合作为小型桌面工具的原型，但上游尚不具备可靠系统配置管理器应有的错误处理与恢复保证。主要问题集中在修改生命周期，而非 Qt Widgets 或 C++ 的选择。

当前结构是：MainWindow 调度五个 ConfigTab；页级代码负责 UI、确认框与命令拼接；GRUB、Services、Autostart 模块负责各自解析；Util 统一执行与状态存储。领域模块已有初步分离，方便修复与测试，但 UI 与授权、持久化和执行过程耦合，操作之间没有统一计划、日志、结果验证或回滚层。

## 主要发现与本轮处置

| 严重性 | 上游问题与影响 | 本轮处置 |
|---|---|---|
| 高 | GeneralTab 忽略提权和自启动写入失败，恢复失败仍清空记录；先改自启动再询问服务确认，取消可丢失恢复信息。旧格式不记录原 target 或完整启用类型。 | 常规页改为只读，保留旧日志并明确不代表真实系统状态；移除该页修改和自动恢复路径。没有宣称修复完整事务。 |
| 高 | GRUB 参数双引号未转义 `$` 与反引号，配置被 root shell source 时可能执行命令。 | 转义 shell 特殊字符，增加真实 `/bin/sh` 字面值回归测试；重复键全部更新。 |
| 高 | 可预测的 GRUB 临时文件名；异步 sudo 启动后立即删除文件，调用方也无法确认结果；备份失败后仍继续。 | 使用 QTemporaryFile，取消无法追踪的异步修改回退，备份/写入失败通过 `&&` 中断。 |
| 高 | DesktopFile 从文件尾扫描组，可能将 Desktop Action 的键当成 Desktop Entry，修改也可能影响错误组。 | 明确组的结束位置，读写仅在目标组内，隔离测试覆盖前后分组及重复 Hidden。 |
| 中 | 只认固定 XDG 目录，忽略 KDE 配置目录优先级与桌面过滤。系统 Hidden 项没有用户文件时无法启用。 | 支持 XDG_CONFIG_HOME / XDG_CONFIG_DIRS、OnlyShowIn / NotShowIn / TryExec，提供完整用户级覆盖，保持系统文件不变。 |
| 中 | 服务保护只在“全部禁用”中实现，可被选中或复选框路径绕过；批量操作仍遍历被隐藏服务。 | 在执行层统一跳过受保护项，批量遵守筛选；enabled-runtime 只读，避免错误转成持久配置。 |
| 中 | 状态与自启动写入使用截断写，未完整检查失败；错误未传播给主窗口，点击确定仍关闭。 | 使用 QSaveFile 与写入检查；自启动 apply 返回失败，主窗口仅在成功时关闭。 |
| 中 | 仅支持 GRUB，却面向任意发行版宣称通用；本机 /boot 普通用户不可读，不能靠文件不存在判断引导器。 | 新增 EFI LoaderInfo 检测，识别实际 Limine 和本次启动项；引导页只读，提供发行版配套只读工具入口。 |
| 低 | 仓库提交了构建缓存/二进制；按钮翻译键缺失；无正式测试与安装规则。 | 停止跟踪 build，新增忽略规则、CTest 和安装目标，补齐按钮翻译。 |

## Limine 写入为什么没有直接实现

本机使用 CachyOS 的配置源、内核更新钩子及快照同步。生成的菜单不是单一程序独占的配置文件：直接覆盖可能破坏快照条目、校验值或下一次内核更新的结果。

Limine 的 EFI 接口虽然声明支持默认项/超时，但配置文件中的值可优先于持久 EFI 变量；直接调用 `bootctl set-default` / `set-timeout` 不能保证实际生效。参见 [Limine 配置说明](https://github.com/limine-bootloader/limine/blob/trunk/CONFIG.md)。本轮仅实现真实检测、信息显示与只读工具入口，不误报完整写入能力。

后续写入后端应通过 CachyOS 配套工具协调配置源、菜单、快照与校验，提供实际读取、变更预览、备份、并发检查、执行验证和失败恢复。不得将 GRUB 的配置模型直接复用到 Limine。

## 尚未解决的限制

- 多数 QProcess 操作仍在 GUI 线程同步等待，授权或命令耗时期间界面可能卡顿；后续应采用异步执行状态机。
- 各页面的按钮立即执行，复选框使用 Apply，操作语义混合；取消不撤销已执行按钮操作。后续统一为变更计划。
- GRUB 仍使用简化行解析，不完整支持 shell 表达式、复杂 submenu 和菜单 ID。重生成失败不会自动恢复上一次文件，也没有配置并发修改检测；本机未验证 GRUB 实际写入。
- 服务分类只按路径判断，不能识别第三方包归属；静态、模板、别名、运行时启用及其他依赖关系不能简单等同于开关。
- XDG 自启动适用性检查覆盖标准桌面筛选与 TryExec，但不模拟所有 KDE/GNOME 私有条件，也不代表进程已经运行；KDE 会话恢复与用户 systemd 服务属于不同机制。
- 关键服务保护名单只能减少误操作，无法证明任意机器的全部关键依赖安全。
- 未进行真实禁用服务、写引导、重启或故障恢复实验。测试通过不等于这些管理操作已在实机验证。

## 推荐后续架构

保持 Qt Widgets 界面，逐步建立以下职责分离，无需重写成大型框架：

1. 只读探测层：系统能力、实际引导器、服务状态、桌面会话。
2. 配置模型层：GRUB / CachyOS-Limine 独立后端，准确区分支持、不可读与不可写。
3. 计划与事务层：保存原状态、展示预览、先完成确认、日志先于变更写入，逐项验证结果。
4. 执行层：参数化命令与受限授权助手，异步完成信号与取消/超时语义，避免任意 shell 脚本接口。
5. 界面层：展示计划与真实结果，失败保留可重试状态，禁止把“已启动执行”显示为“已成功”。

## 验证

本轮配置写入测试仅使用 QTemporaryDir，不操作真实用户配置。CTest 包含核心 shell 转义/状态持久化测试、XDG/KDE 自启动回归和五标签 GUI 冒烟测试。实际系统探测使用普通用户 `--check`。最终实机和构建验证结果记录在交付说明中。
